# Shared OS icons

Apps do not ship icon fonts or bitmaps. Every host resolves a small, shared
icon **name** registry to its native artwork, so the same MBC bytes paint the
same icon on ESP32 (LVGL), macOS (LVGL + SDL3) and the Web Player (WASM + DOM):
a Font Awesome symbol glyph on the devices, an inline stroke SVG on the Web.

* Registry: `crates/micro-ir/src/icons.rs` (`ICONS`, `icon`, `is_icon_name`,
  `glyph_for`, `svg_for_size`).
* Widget: `ui.icon(name, options)` — MBC **v26** adds `UiKind::Icon`.
* Manifest: `app({ icon })` accepts a catalog name as well as the legacy
  single letter.

## API

```ts
ui.icon("settings", {
  textStyle: { font: "uiSans", size: 24, weight: "regular", lineHeight: 32 },
  tone: "muted",     // ink (default) | muted | accent | inverse
  variant: "badge",  // plain (default) | badge (circular sage field)
  onClick: () => { … },
});

// A bound name re-resolves when the value changes (RenderPatch::SetIcon).
ui.icon(bind(() => os.appIcon(0)), { tone: "accent", variant: "badge" });
```

Rules:

* `name` is either a catalog name or a **single** display glyph (legacy App
  letter marks). Any other literal is a compile error (`MTS012`).
* `textStyle.size` is the only size input: `12 | 14 | 18 | 24 | 32`; the
  default is `24` (`TextStyle::DEFAULT_ICON`).
* `tone` and `variant` are interned into `options` as two consecutive strings
  (`tone`, then `variant`), always both, so hosts read them by position.
* Icons are decorative by default. A plain icon does **not** swallow taps meant
  for a card surface; give the icon itself `onClick` only when it is the
  control. That icon then becomes tappable (`data-tap`, `role="button"` and
  Enter/Space on the Web, a clickable LVGL box on native).
* Unknown names that reach a host degrade to `?` plus a diagnostic; the
  compiler rejects them first.

## Catalog

42 names, alphabetically sorted in `ICONS`:

| Group | Names |
| --- | --- |
| Navigation | `apps`, `down`, `home`, `left`, `list`, `next`, `prev`, `refresh`, `right`, `up` |
| Files & editing | `copy`, `download`, `drive`, `edit`, `file`, `folder`, `image`, `save`, `trash`, `upload` |
| Media | `music`, `mute`, `pause`, `play`, `stop`, `video`, `volume` |
| System & status | `battery`, `bell`, `bluetooth`, `check`, `close`, `eye`, `keyboard`, `location`, `mail`, `minus`, `plus`, `power`, `settings`, `warning`, `wifi` |

Each entry stores:

* `glyph` — the Font Awesome symbol codepoint present in the generated
  `micro_icons_*` subset faces.
* `path` — a 24×24 stroke path (`currentColor`, 2 px, round caps/joins).

## Host rendering contract

| Host | Painting |
| --- | --- |
| ESP32 / macOS (LVGL) | `lv_label` with the matching `micro_icons_*` subset face (12, 14, 18, 24, 32 px), inside a transparent box the Delphi layout sizes. `badge` paints a circular `0xE7F0E5` field; `tone` selects the text colour (`ink 0x101820`, `muted 0x84937D`, `accent 0xC0683B`, `inverse 0xFFFDF7`). A non-clickable icon removes `LV_OBJ_FLAG_CLICKABLE`. |
| Web | `<span class="micro-icon">` containing the inline SVG at the requested intrinsic size; `data-tone` / `data-variant` drive CSS colour and the circular badge. A single glyph falls back to text at `size_px`. |

### Storage and memory

The icons cost **~21 KiB** of flash in total, not the ~110 KiB that four full
Montserrat symbol faces would need. The device fonts are dedicated 42-glyph
Font Awesome subsets generated by `scripts/generate-icon-fonts.py`
(`assets/fonts/lvgl/micro_icons_{12,14,18,24,32}.c`, 2 bpp at 12/14 px and
4 bpp at 18/24/32 px, RLE-compressed). They are `const` glyph data in flash
(packed payload ~20 KiB): icons add no persistent font RAM, only the two small
LVGL objects (box + label) the renderer already creates per icon. The only
Montserrat face left enabled is 14 px for the host app bar's Wi-Fi symbol.

Required build flags (already set in-tree):

* `native/lv_conf.h` and `firmware/micro-os-esp32/sdkconfig.defaults` keep
  `LV_FONT_MONTSERRAT_14` for the app bar and enable
  `LV_USE_FONT_COMPRESSED` for the RLE icon fonts.
* The generated `micro_icons_*.c` must be listed in both
  `native/CMakeLists.txt` and the ESP32 `micro_runtime_ffi` component.
* Web CSS lives in `products/micro-web-player/src/style.css`
  (`.micro-icon`, `[data-tone]`, `[data-variant="badge"]`).

The App text faces (`MicroUiSans`, `MicroUiIpa`) do **not** carry the
private-use symbol codepoints — that is exactly why the icon widget switches
to the Font Awesome subset face instead of reusing `ui.text`.

## Launcher cards and accessibility

The home screen (`apps/shell`) paints each card as:

1. a tappable `ui.surface("paper", { onClick, label: "Open Counter" })`;
2. a decorative `ui.icon(..., { variant: "badge" })` above it;
3. decorative `ui.text` title/caption above that.

`ui.text` and `.micro-icon` are pointer-transparent on the Web and labels are
non-clickable in LVGL, so taps land on the card. On the Web, a tappable surface
emits `role="button"`, `tabindex="0"` and the literal `label` as `aria-label`,
and Enter/Space activate it. App manifest icons keep the same visual language:
`icon: "plus"`, `"settings"`, `"edit"`.

## Adding an icon

1. Append `icon!("name", "\u{fxxx}", "M…")` to `ICONS` in
   `crates/micro-ir/src/icons.rs`, keeping the list alphabetical; use a Font
   Awesome 5 codepoint present in `FontAwesome5-Solid+Brands+Regular.woff` and
   a 24×24 stroke path.
2. Update the unit test's count and add the name to a doc table above.
3. Regenerate the device fonts:
   `python3 scripts/generate-icon-fonts.py` (needs the pinned LVGL checkout
   for the Font Awesome woff), then `cargo test -p micro-ir` (registry
   invariants) and `npm run build:app` to recompile Apps against the name.

No generated font binary, license file, or per-host asset table changes: the
name is the whole contract.
